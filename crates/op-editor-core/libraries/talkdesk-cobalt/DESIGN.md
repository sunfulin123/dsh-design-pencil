# Design System: Cobalt Design Tokens

> Source: Figma file "0 - 🏷️ Design Tokens" (`wFqyJnLISAbPa0Si9UBTP9`), last modified 2026-09-11. Pages: Colors (`2:1863`), Fallbacks (`6299:242`), Typography (`0:1`), Spacing+ (`6:600`). Light values were checked against styles.json, and dark values against the stylesheet (theme-light 4.1.3): https://prd-cdn-talkdesk.talkdesk.com/cobalt/theme-light/4.1.3/styles.json and https://prd-cdn-talkdesk.talkdesk.com/cobalt/theme-light/4.1.3/styles.css

## Overview

**Creative North Star: "The Contrast-First Ramp"**

Cobalt color is generated, not hand-picked. Each family is a 12-step ramp, plus 12 transparent steps, built with the Radix algorithm from the primary and background colors, so contrast is designed in. Each step has one job, and the same step does the same job in light and dark themes, so a screen can switch theme without new decisions. The character is calm and precise: one sans family per platform, a 4px-based spacing rhythm, and depth from shadows in light theme. In dark theme, depth comes from surface tone, because shadows are not inverted.

Figma gives three reasons for the "Colors 2.0" update: accessibility, dark theme support, and white-label theming.

Getting Started defines design tokens as the design atoms of the system: named entities that store visual attributes such as typography, color, spacing and shadow, kept as data and used directly by the component libraries. The library has Core components (stateful, shared by all products with the same language) and Patterns & more (for prototypes). Only the Cobalt design team updates it. To use it, activate the library first: open the Assets tab, click the Team library icon, then enable the library in your file. Full guidelines are on Zeroheight: https://designsystem.talkdesk.com/51aaf6147/n/8243b2

**Key Characteristics:**
- 10 color families, each with 12 solid steps and 12 alpha steps, in light and dark themes
- Semantic roles (Primary, Secondary, Info, Success, Warning, Error) are aliases of primitive families
- Text colors are steps 11–12 of a family, or the gray-8 placeholder
- Roboto on web and Android; SF Pro on iOS
- Shadows in light theme; surface tone for depth in dark theme

## Implementation

Build TD screens with the Cobalt components first. The `@talkdesk/cobalt-react-*` packages (for example `button`, `tag`, `message`, `input`, `tab`, `popup`, `icon`, `typography`, `box`, `flex` and `theme-provider`) already apply these tokens. Write custom CSS only for what they do not cover, and use the CSS names below.

- **Stylesheets.** The page loads Cobalt's base stylesheet, `https://prd-cdn-talkdesk.talkdesk.com/cobalt-design/v27.0.0-1/cobalt.css`. It imports Roboto (weights 300, 400 and 500) from Google Fonts, and it includes the Material Icons TD font. React apps get Roboto and Roboto Mono from `@talkdesk/cobalt-css-core`, which imports `cobalt-utils/cobalt-fonts/font-face.css`. Do not load these fonts again. The theme stylesheet is `https://prd-cdn-talkdesk.talkdesk.com/cobalt/theme-light/{version}/styles.css` (`{version}` is the template placeholder; `4.1.3` is the version this document was checked against, for example `https://prd-cdn-talkdesk.talkdesk.com/cobalt/theme-light/4.1.3/styles.css`). It holds both the light and the dark values.
- **Theme switch.** Set `data-co-colorscheme` to `light` or `dark` on `<html>`. In Atlas, the user's mode (`light`, `dark` or `system`) is resolved to one of these two values. Do not create dark variables, dark classes or a second stylesheet. The same variable names change value, so colours, type, spacing and radius need no theme branches. Three things differ by theme: the accent wash (solid steps in light, alpha steps in dark), the message gradient (last stop and angle), and elevation shadows, which are removed in dark (see Gradients and Elevation).
- **Names.** Use the CSS names below. Frontmatter keys are not variable names: `body`, `label`, `caption` and `scale-*` are not variables. Compose typography from the size, weight and line-height tokens. Spacing and radius both have a `small` step, so use the CSS name: `--spacing-small` is 16px and `--border-radius-small` is 8px.
- **Not in the tokens.** Component sizes, interaction states, input borders, focus-ring width and offset, icon sizes, layout grid, breakpoints and motion are not defined in this document. The inset tokens (`--spacing-inset-femto` to `--spacing-inset-xmega`) exist, but the file does not say which component uses which one. Take component values from the Cobalt components, and do not invent them from spacing tokens. The file's borders use steps 6–8. Step 8 is about 1.9:1 on white in light and 2.8:1 on `#1A1A1A` in dark, below WCAG's 3:1 for a field boundary that is needed to identify the field. `secondary-9` is about 3.3:1 on white and 3.4:1 on `#1A1A1A`, so it meets 3:1.

## Colors

### Collections and roles
The Figma file has two variable collections. "Color scheme (Primitives)" holds the static values for light and dark. "TD theme" holds semantic values: text colors, sizing, border width and radius.

Colors are variables, not styles. The file says gradient stops are variables too, so each gradient has light and dark values.

The Read Me's "What changed from version 1?" says Colors 2.0 replaces the old Basic and Secondary styles. Gray corresponds to the old Basic style. Neutral is the primitive behind Secondary. The palette algorithm generates Neutral from the primary and background colors, so Neutral can change when the primary color changes. The palette is generated with the Radix algorithm. The file points to a Radix reference Figma file, which is not in this data.

| Role | Primitive family | Use |
|---|---|---|
| Primary | Purple | Brand color. `purple-9` is the main shade (Talkdesk Purple) |
| Secondary | Neutral | Interactive elements, and tags that carry status color |
| Info | Blue | Informative content |
| Success | Green | Positive outcome |
| Warning | Yellow | Warning |
| Error | Red | Error |
| (none) | Gray | Non-interactive elements: text and dividers |
| (none) | Midnight, Teal, Orange | Defined as primitives; the Colors page gives them no semantic role |

The file says: "The Neutral should not be used directly. It is a primitive that is supposed to be used by the semantic of Secondary."

### Primitive ramps
Solid steps 1–12 are in the frontmatter as `family-N` (light) and `dark-family-N` (dark). In CSS, both are the same variable, `--family-N`, and the dark value applies when `data-co-colorscheme` is `dark` (see Implementation). Alpha steps are in the tables below, as `--family-aN`.

Step roles (from "How to use variables" in the file):
- **1–2**: backgrounds of UI elements
- **3–5**: interactive elements and their states
- **6–8**: borders and separators
- **9–10**: solid fills, such as filled buttons, banners and toasts. Step 9 is each family's main shade.
- **11–12**: accessible text and icons on steps 1–2 and `background-color`
- **Alpha steps (a1–a12)**: borders, component states, and color that lets the background show through

**The Ninth-Step Rule.** Step 9 has the same value in both themes for eight families (blue, green, midnight, orange, purple, red, teal, yellow). Gray and Neutral change: gray-9 is `#898E93` in light and `#D7DBDE` in dark, and neutral-9 is `#888E92` in light and `#696E72` in dark. The file's text names only gray as an exception. The production stylesheet's dark block shows that neutral-9 changes too.

**The Contrast Pair Rule.** The file pairs text with background as step 11 over step 2, for example `purple-11` over `purple-2`, in both themes. Solid step 9 pairs with `variable-contrast`, which passes contrast over the solid, for example `purple-contrast` over `purple-9`. Values for both themes are under Supporting variables. In light theme the contrast is white on every family except yellow (`#2C1F09`), because yellow-9 is light. In dark theme it is white except gray (`#0E2433`) and yellow (`#2C1F09`). The contrast token is documented for step 9 only. Banners and toasts can also use step 10 (see Primitive ramps), and the file gives no contrast token for it, so check that text colour yourself.

### Source notes
- Values come from the variables bound to each swatch, not from the text labels next to them. Labels disagree with the variable value for 103 of 796 token rows, and 62 of those differ by more than 4 units per channel. The largest gaps are in dark Neutral/Secondary steps 9–12, where the labels show green values (`#00874F`, `#007942`, `#67D093`, `#9FF7C0`) but the variables are gray (`#696E72`, `#767C80`, `#AEB4B8`, `#EAEEF1`). Some alpha labels are also stale.
- Some layer names and labels are out of sequence. In Gray, frame names run one number ahead of their labels (frame `Gray-9` holds `gray-8`), and `orange-a6` is labelled `orange-6`. Names here follow the variable ID order, with label text for teal. Each family has 12 solid and 12 alpha steps.
- The Fallbacks page repeats the Primitives variables: all 240 have identical values. Its image rectangles show old Legacy scales (10 distinct strip images, for example purple and blue), with CSS-style names such as `--purple-200` to `--purple-900` and hex values. These are the legacy scales that styles.json still defines (for example `purple-800` is `#1C0140`). They are not Colors 2.0 steps, and the file does not say what "fallback" means here.
- In the Figma file, `variable-contrast`, `variable-surface`, `variable-track` and `variable-indicator` have no values, which leaves 24 variables per family. styles.json has all 28 per family (12 solid, 12 alpha and these four). Its values for both themes are under Supporting variables.
- styles.json (theme-light 4.1.3) matches Figma on every light value that both files define: 133 solid, text, background and surface values, 120 alpha values, and the semantic aliases (`primary` is purple, and so on). It holds light values only. The one difference is the Level 4 indicator shadow spread (see Indicator Shadows).
- Dark values come from the same stylesheet, `theme-light/{version}/styles.css`, not from a separate file. All 133 dark values (with `var()` resolved) and the 120 dark alpha values match Figma.
- Mechanism: Atlas sets `data-co-colorscheme` on `<html>` to `light` or `dark` (the setter in `packages/ui/src/ui.js` is typed `'light' | 'dark'`). The stylesheet has a `:root, [data-co-colorscheme="light"]` block and a `:root[data-co-colorscheme="dark"]` block. The dark block redeclares 471 color variables under the same names (source: `packages/themes/base/src/_dark-colors.scss`). Typography, spacing, radius, shadow, opacity and z-index variables are declared once and shared by both themes. For dark mode, Atlas returns no JSON when the stylesheet-only flag is on and the app declares `darkMode`, so the light inline variables do not override the dark stylesheet.
- styles.json uses CSS custom properties with these token names: `red-1` is `--red-1`, `text-default` is `--text-default`. The exception is `background`, which is `--background-color`.
- Legacy scales: styles.json still defines `purple-200` to `purple-900`, and the same steps for blue, green, yellow, orange, red, teal and midnight. `gray-100` to `gray-900` and `secondary-100` to `secondary-900` point to `basic-100` to `basic-900`, the old Basic gray. `basic-100` is `#FAFAFA`, while gray-1 is `#FBFCFD`.
- Other groups in styles.json: `brand-*`, `feature-*` and `tertiary-*` alias the legacy scales, and `workspace-*` aliases the primary and secondary steps. `illustration-*` holds the Copilot illustration colors, `border-focus-color` is the focus ring, and the `overlay-*` tokens are the scrims.
- Figma's Variables API returned 403 for the token used, so modes and names come from the node data.
- Frame 165, "Helper colors", lists four annotation colors by hex label: Token `#74A1FB` (labelled `$helper-token`), Spacing `#FF7101` (`$helper-spacing`), Inset `#00F545` (`$helper-inset`) and Variant `#7B61FF` (`$helper-variant`). They annotate the documentation. Do not use them in product UI.

### Named Rules
**The One Family Rule.** Each platform uses one sans family: Roboto on web and Android, SF Pro on iOS. Roboto Mono is the mono token. Build hierarchy with size, weight and line height, not with a second typeface.

## Layout
The source defines spacing, radius and type scales. It defines no grid, container width or breakpoints, and styles.json has none either. **[To be resolved during implementation: grid, container widths and breakpoints are not in the tokens file.]**

Spacing rhythm: the unit is `spacing-base`, 4px. Stack steps (`nano` to `xtera`) are multiples of 4px: 4, 8, 12, 16, 20, 24, 32, 40, 48, 56, 64, 80 and 120px. `femto` (1px) and `pico` (2px) are the steps below 4px. Inset steps (`inset-nano` to `inset-xmega`, 4 to 48px) are equal vertical and horizontal padding, and `inset-femto` (1px) and `inset-pico` (2px) sit below them. The file gives each inset step the same value as its stack step. styles.json also has `base-spacing-0` to `base-spacing-12`: 0, then multiples of 4px up to 48px.

## Elevation & Depth
Light theme uses layered black shadows. Dark theme does not invert shadows; it steps surface tone instead (see Surfaces). The shadow values are the same CSS in both themes. Because the Tonal Dark Rule says not to use shadows for elevation in dark theme, leave `--shadow-N` off elevated components in dark. There is no `none` shadow token.

## Do's and Don'ts

### Do:
- **Do** use semantic roles (Primary, Secondary, Info, Success, Warning, Error) in components. They point to the primitive families.
- **Do** use Gray for non-interactive elements (text, dividers), and Secondary for interactive elements (buttons) and status-colored tags.
- **Do** use step 9 for solid fills, and steps 11–12 for text and icons.
- **Do** use `text-description` for placeholders on inputs without a visible label, and `text-placeholder` only when the label is visible.
- **Do** use alpha steps for borders, component states, and color that lets the background show through.
- **Do** build dark-theme depth with `surface-elevation-1` to `surface-elevation-3`.
- **Do** switch themes with `data-co-colorscheme` on `<html>`. Components need no theme branches.
- **Do** use the message background gradient for Copilot Message fills, and the brand gradient for Copilot Button fills and the advisor icon.

### Don't:
- **Don't** hand-pick shades. Use ramp steps, which were generated for contrast.
- **Don't** use Neutral directly. It is the primitive behind Secondary.
- **Don't** apply `variable-surface`, `variable-track` or `variable-indicator` directly. They are supporting variables.
- **Don't** use step 9 as a text color. Use steps 11–12.
- **Don't** use shadows for elevation in dark theme.
- **Don't** take values from Figma text labels. The bound variables are authoritative (see Source notes under Colors).
- **Don't** fill a Message or a Tag with the brand gradient. The file marks both NO.
- **Don't** stroke large boxes with the message background gradient. The file marks these NO.
- **Don't** use the helper annotation colors (Token, Spacing, Inset, Variant) in product UI.
- **Don't** use the legacy scales (`purple-200` to `purple-900` and the others, plus `basic-*`) in new work.
- **Don't** create `dark-*` variables or dark-only classes. Keep the same names and let `data-co-colorscheme` switch the values.
- **Don't** put `background` text on step 9. It is about 1.8:1 on purple-9 in dark. Use the `*-contrast` token there, for example `primary-contrast` (9.8:1 in both themes). On step 12, `background` is the text colour (about 13:1 in both themes). Do not use `primary-contrast` on `purple-12`: it is 1.3:1 in dark.
- **Don't** use frontmatter keys such as `body`, `label`, `caption` or `scale-*` as CSS variables. Use the CSS names in Implementation.
