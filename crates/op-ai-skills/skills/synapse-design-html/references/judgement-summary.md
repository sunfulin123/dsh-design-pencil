# Judgement summary

Stage summary of [the shared judgement guide](judgement.md). Read the full guide only when the Skill's loading table selects it.

**Precedence:** user > selected `DESIGN` > build rules > domain guides > this guide. Where a `DESIGN` value would make content unreadable or a control unusable, keep it usable and record the departure with its reason.

**Surface mode** comes from the user's immediate goal on each screen, never the industry. `Operate` (dashboards, lists, consoles, editors, settings): task completion and scanability first; build the shell and dominant work surface first; one density tier per screen; no marketing hero, invented controls or display fonts on labels and cells. `Persuade`: offer, audience, proof and one working primary action in the first viewport. `Read`: calm reading column with clear wayfinding. `Experience`: the artifact fills the first viewport with quiet chrome.

**Content states:** evaluate `loading`, `empty`, `error`, `partial`, `success`, `permission` for every journey and data surface; design each or record why it is `not-applicable`. An empty state says what belongs there, why it is empty and one next action, never a bare "No data". Inputs keep persistent labels; selects keep a `12px–16px` chevron inset and an `8px–12px` gap after the value; validation sits beside the field and says how to fix it; destructive actions name the object and consequence. Layouts survive long unbroken text, 0/1/100+ items, large numbers and 30–40% text expansion.

**Copy:** English by default unless the user asks for another design language; one language per screen. Lead with the fact the user needs, then the next action. Use `verb + object` labels and consistent terms. Preserve user facts, label sample data, and never invent testimonials, claims, logos or system status.

**Design judgement:** every decision traces to the user, task and success criterion. Settle structure and reading order before style. Use three levels of space: within a group `4–8px`, between groups `24px+`, inside a component its own padding; a heading sits nearer its content than the group above; siblings share indent and spacing; badges keep an edge inset; no spacer nodes. One primary region and one primary action per screen, built from scale, weight, position and space. Siblings share anatomy and behaviour. Check optical alignment in the render. Translate a style's colour roles and type character while sizing density from the task; record departures. Check contrast, line length, hit areas, labels and focus.

**Blocking quality floor:** missing content (blank text, unapplied override or unloaded asset is not whitespace); unreachable action (`44px` recommended, below `24px` critical); clipped or overflowing content; overlap; missing key state; broken hierarchy; unreadable text; untruthful content (placeholders, lorem ipsum, mixed-language chrome, invented claims, dead controls). Repair and re-check, or report the unfinished scope. Below the floor: restrained elevation without nested cards, structure from real content rather than automatic equal card rows, visible control states, labelled inputs and identifiable icon-only controls.

**Evidence:** a produced screenshot is not an inspected one, clean diagnostics are not a pass, and an applied change is not a saved file. Each check is `pass`, `fail`, `unverified` (say what was not covered) or `not-applicable` (say why); never report `pass` to satisfy a gate. Evidence names what was examined, how, the finding and what was not covered, for one version. Classify each primary action `verifiable`, `visual-only` or `not-implemented`; an "unavailable" notice means `not-implemented`. Continuing from a POC or reference keeps its screens, states, copy and actions; record craft upgrades as `{what, why}`; dropping a screen, shell, state, copy or action is a substantive deviation that needs the user's approval first.

**Rubric:** one check each for `task_integrity`, `structure_overflow`, `hierarchy_density`, `style_consistency` and `content_states`, with status and evidence.
