# POC review summary

Stage summary of [the POC review guide](../poc-review.md). Each paragraph names the section that holds the detail; read that section when the Skill's loading table or a failure makes it necessary.

**Before implementation** ([01](01-before-implementation.md)): bind the exact DESIGN with `resolve-theme.mjs`; never handwrite a substitute. A failed preflight is a diagnosis to fix. Establish the main business state and action results first, derive linked views from the same sample data, and label illustrative data.

**Revisions** ([02](02-local-revisions.md)): name the affected region and interaction, batch related fixes, then check only those `dev --sessions`; shared components, global CSS or responsive changes widen the check. Prior evidence becomes historical after any source change; finish with one current build and final review.

**Development server** ([03](03-start-and-reuse-a-local-development-server.md)): start and own it yourself. For Cobalt in SS install only with `synapse_design_prototype` `install`; never run `pnpm`, `npm` or `yarn` `install`/`add`/`i` in a shell while that tool is available. Run `pnpm run dev`, use Vite's reported loopback URL, wait for HTTP success, reuse the process for HMR, and stop only processes you started. Preview configuration is not a prerequisite.

**Visible review** ([04](04-review-the-visible-page-with-browser-use.md), [05](05-review-long-content-without-claiming-unseen-cove.md)): prefer Browser Use. `browser_open` the URL, confirm real content with a read and screenshot, operate the business iframe through observed refs and frames, and verify each result. Use `browser_screenshot({ quality: "original", viewport: true })` for acceptance evidence. Never replay an uncertain business action. For long content, scroll about 80% per step, capture each view, stop at 20 screenshots per target and report the rest as unverified.

**Headless fallback** ([06](06-headless-development-fallback.md), [07](07-frame-aware-actions-and-detail-images.md)): `review-poc.mjs dev --url <url> --source <task-dir> --out <task-dir> --temp <temp-dir> --steps <temp-dir>/review/steps.json --sessions main,dialog,drawer`. Plans use `frame` for business iframes, `waitFor` with `stable: true` before screenshots after transitions, and `selector`/`clip` crops that supplement, never replace, full viewports. Development output never becomes handoff evidence.

**Final review** ([08](08-final-review-after-related-changes-are-complete.md)): after related fixes, run `review-poc.mjs final --project <task-dir>/project ... --scope app` for Cobalt or `final --entry <task-dir>/preview.html ...` for ordinary HTML, both with `--source <task-dir> --out <task-dir> --temp <temp-dir> --steps <temp-dir>/review/steps.json`. It covers 390x844, 768x1024 and 1440x900 in one browser and leaves accessibility, visual and responsive review, content states and actions pending. Inspect the captures and action results, record only what you observed, then run `verify-surface.mjs --check-evidence <task-dir>/evidence-report.json`. Any later edit needs a new final run. If Chromium stays unavailable after its retry, record unverified rendered coverage with `verify-surface.mjs --url <static-entry>` and never invent pass statuses.
