# OP composition

Build an editable hierarchy with meaningful node names. Before constructing detail, identify the main focal area, primary action and functional groups. Group related content through proximity; use surfaces and separators only where they clarify structure. Avoid nesting decorative cards or using equal card grids as an automatic page structure.

Use flow layout and content-driven sizes for ordinary sections; fixed sizes are appropriate for deliberate viewports, media and controls. Align related edges and baselines, use consistent spacing for repeated rows, and leave enough room for realistic copy. Give headings more separation from preceding groups than from the content they introduce. Apply the typography and spacing scale of the selected DESIGN; do not silently substitute a competing preset.

Operational screens need stable controls, readable tables, clear selection and enough density for the task. Promotional surfaces need a coherent focal point and deliberate section rhythm. Reading surfaces need comfortable line lengths and a clear hierarchy. On smaller screens, reflow the actual content rather than simply shrinking a desktop board. If multiple sizes were requested, create and inspect the corresponding OP boards; these boards alone do not prove browser responsiveness.

Use existing components, variables and shared styles first; create reusable definitions where repetition warrants them. Preserve existing instance overrides and local edits. Consider readable contrast, visible control states, labels and appropriately sized touch targets for the intended surface. Provide interactions and additional content states when they serve the task and available OP capabilities support them. Never claim an unimplemented interaction works.
