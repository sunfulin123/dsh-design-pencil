# Direction and content

Determine the primary user task, domain vocabulary, required screens and most important action before deciding hierarchy. Keep user-supplied facts, workflows and content. Do not invent customer claims, figures, testimonials, real logos, contact details or image provenance; identify illustrative content as an assumption.

Choose the surface by the user's immediate goal, not the company's industry:

- **Operate:** dashboards, tools and settings prioritize scanning, recognizable controls, compact useful information and stable actions. Decorative imagery must earn its space.
- **Persuade:** a product introduction needs a clear offer, a visible primary action and a concrete demonstration. Select a focal element that supports the actual product.
- **Read:** documentation and long-form information need clear wayfinding, comfortable text measure and an undistracted reading area.
- **Experience:** portfolios and visual showcases let the actual work lead while navigation stays legible and secondary.

Inherit established design decisions unless the user requests a redesign. Where existing brand information is incomplete, preserve confirmed elements and derive missing details from the selected DESIGN rather than guessing a real brand's values. Avoid a category's predictable default layout; choose structure from its content and task. Do not force a marketing hero into an operational interface.

Use clear domain nouns and concise labels. Button text should say what the action does. Empty and error states should explain the situation and a useful next step when the task warrants them. Write all UI copy inside the design in English by default unless the user explicitly requests another UI language (keeping one consistent UI language across the screen), and distinguish real content from illustrative samples.
