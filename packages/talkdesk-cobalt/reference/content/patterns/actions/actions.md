# Actions

## Guidance

:::note
This page doesn't map to the spec's Interaction Patterns categories (Forms & Validation, Search/
Filtering/Sorting, Empty States & Loading, System Notifications & Alerts, Onboarding & Wizards, Data
Visualization) — flagged for review. Sourced from the live Cobalt DS's Actions pattern page.
:::

Actions are usually associated with the header or the bottom of the page — their position depends on
the use case.

## When the user needs to interact with elements before interacting with the actions

* Actions go at the bottom of the page, aligned left.
* The primary action is positioned on the left.
* Destructive actions align to the right, separated from primary/secondary actions by a vertical
  divider.

## When the user is editing a form and doesn't need to interact with all fields first

* Actions go at the bottom of the page, aligned left, and stay always visible.
* The primary action is positioned on the left.
* Destructive actions align to the right, separated by a vertical divider.

## When the user doesn't need to interact with (most) elements before interacting with the action

* Actions associate with the header, aligned right.
* The primary action is positioned on the right.
* Destructive actions are positioned to the left, separated by a vertical divider.
