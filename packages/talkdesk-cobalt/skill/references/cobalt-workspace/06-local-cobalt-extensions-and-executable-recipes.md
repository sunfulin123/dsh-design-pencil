## Local Cobalt Extensions and executable recipes

The project helper copies every extension implementation and its local types/styles to `src/components/cobalt-extensions/`. There is no extension package.json, npm dependency, file dependency or package alias in the generated project. Read the copied files before adapting them. `cobalt-reference/registry/authoring.json` resolves the matching full source, API docs and examples; generated project metadata points to its local copied files. The official dependency baseline lives in the copied `dependencies.json`.

Created projects include List page, Detail page, Form page, Active call, Echart insights, Card widgets, ECharts gallery and Schedule page source recipes. Search the authoring registry, read the selected Markdown contract and every linked support file, then adapt its local source. Card widgets replaces the compact Users list example and includes metric/donut, template, empty, use-case, sentiment, keyword and shift distribution references. ECharts gallery covers prediction/history, stacked forecast and scenario comparison. Mount Schedule page in the existing WFM team-schedule page; preserve its sticky columns/headers, scroll-only timeline and fixed pagination. Pass usePrototypeScenario() only to recipes whose Props accept scenario. Recipes contain local sample data and explicitly document unimplemented backend behavior. Copying a recipe alone is not a completed design.

For component discovery, start with `cobalt-reference/AI-INDEX.md` for the official component selection rule and the current recommended extensions. Search `registry/authoring.json` by name or purpose. Read the exact published API or the chosen extension's source, types, styles and example before coding. The generated project keeps these indexes and linked docs locally.
